Case study — Method

How I build with agents

The two case studies beside this one were built by multi-agent pipelines I direct. So was this page. Agent leverage is real — and so is drift, and most "AI-assisted" work ships the drift. This is the method that keeps mine out: scripted orchestration, adversarial review with four lenses, and a human who signs every fix and every rejection. Nothing ships ungated.

01 01 The claim

The raw output lies a little

Every claim on the other two pages of this site traces to a test, a gate, or a critique. This page owes you the same honesty about how the pages themselves get made — because they were built by crews of five to nine agents, and "built by AI agents" is, in most portfolios, a warning label.

The leverage is real. A scripted run can read two private repos, draft copy from what it found, build a page, and review it from four directions in the time it takes a human to write an outline. The drift is just as real: agents fabricate numbers that sound plausible, soften sharp claims into mush, praise their own output, and wander off-brief the moment a task runs long. Most AI-assisted work ships both halves — the speed and the drift — and a careful reader can smell it in a paragraph.

So the engineering problem was never "use agents." It is the same problem as Cairn's ghost postings — dead listings a job scraper must catch — and Trading Lab's flattering backtests — simulated profits that won't survive live data: the raw output lies a little, and the system around it has to stop that. My answer is the same in all three places — gates. Deterministic orchestration where determinism belongs, adversarial review before anything ships, and one human — me — making every judgment call, on the record.

02 02 The run

Anatomy of a run

A typical run has five to nine agents in four phases, and the shape matters more than the headcount.

Scouts first. Before anything gets written, researcher agents fan out in parallel — for a case study, two analysts each deep-read a different private repo and return a receipts file: every claim pre-verified against the code it describes. The writers downstream never touch the repo; they touch receipts. A writer with only receipts in context has no repo to misremember — and any number that isn't in the receipts file is a finding, not a fact, when the panel cross-checks.

Then concept fan-outs, with assigned angles — a fan-out being one brief handed to several agents at once. When this site needed copy, three copywriter agents attacked the same brief from deliberately different directions — a minimalist, a vivid-imagery writer, a recruiter-optimizer — and a judge agent scored every resulting option against explicit criteria, killing cliches, duplicates, and anything fabrication-adjacent. Parallel agents given the same prompt converge on the same safe median; the assigned angles are what buy actual range.

Then one or two builders turn the winning concept into the artifact. Then the adversarial review panel — the part that earns the whole method, and the next section. A fixer applies what survives.

The division of labor is strict. Phases, fan-outs, and barriers — sync points where every agent in a phase must finish before the next phase starts — are scripted: the runs are Claude Code agent workflows. A run is a program, not a conversation, and an agent cannot skip review because it feels done. What stays human is judgment: the brief, the scoring criteria, and every triage decision — fix it, or reject it with a written reason — on every finding.

03 03 The review panel

Four lenses, and the right to be overruled

Four reviewer agents run in parallel against the built artifact, each with a distinct lens and an explicit mandate to find problems, not to approve.

  • Correctness — reads the code: tag balance, broken scripts, dead anchors, the defects a linter should catch and a tired human skims past.
  • Design — checks system consistency: tokens, spacing, type scale, whether the page still belongs to its siblings.
  • First-glance — roleplays a cold reader with a hiring manager's patience and no obligation to finish, hunting comprehension stalls — the sentence where a senior engineer stops trusting the page.
  • Sensitivity — audits for discretion against an explicit never-publish list, because a portfolio is a public surface over private work.

Every finding is triaged by me: fixed, or rejected with a written reason. Both verdicts matter, and two incidents show the gates biting in both directions.

The sensitivity reviewer once over-applied its rules and scrubbed accurate career facts — a real team name — off the resume-facing pages. Flagged correctly by its own lights; wrong anyway. A portfolio that contradicts your resume is worse than the risk that rule guarded, so I overruled the finding and restored the facts, with the reason written down. Automation flags; humans decide.

The design reviewer caught the homepage schematic being framed as "live telemetry — not a mockup" when it is a scripted animation. A senior engineer would clock the loop in seconds and distrust everything after it. The copy shipped as "drawn in code" instead. The honesty this site trades on is not a vibe — it is a review lens with findings, and this one drew blood before launch.

04 04 Resilience

A stray click costs minutes, not the afternoon

One nine-agent run died mid-flight to a stray click. The afternoon didn't.

Every agent result is journaled the moment it lands — the orchestration treats agent output the way Trading Lab treats trades: append-only records written at the time, never reconstructed from memory afterward. Eight of nine results came straight back out of the journal, and only the final stage re-ran. Total cost of the kill: minutes.

That property is designed, not lucky. Checkpointed orchestration means a run is resumable at every phase barrier; a crash, a rate limit, or a fat-fingered interrupt costs the stage in flight, never the run. It is the same instinct as the golden masters in Cairn — snapshot tests that pin a system's output byte-for-byte — and the append-only event log in Trading Lab: if the work isn't journaled, it didn't happen; if it is, you never pay for it twice.

05 05 The receipts

What six runs cost, and what they bought

Numbers over adjectives. Across all six runs that built this site and its case studies, the adversarial panels returned 164 findings — the per-run counts are in the ledger below — every one triaged, fixed or rejected with a written reason, before anything went live. Runs are five to nine agents and burn hundreds of thousands to roughly a million tokens of agent work each. A full case-study pipeline — repo mining to draft to build to four-lens review to fix — completes in roughly 20 to 30 minutes of wall clock. The homepage redesign, the largest run, took about two hours.

Honest accounting cuts both ways: those minutes buy drafts and defect lists, not judgment. The briefs, the criteria, and 164 triage decisions are human time, and they are the part that makes the rest worth anything.

This isn't a side-project trick, either. The day job is building AI-agent skills on MCP servers at Oracle. The stance doesn't change: I direct, agents execute, gates decide.

06 06 The test

This page went through the same pipeline

The standfirst's promise started as practice, not copy. Trading Lab's gate keeps saying FAIL until a strategy earns PASS. Cairn's golden masters let no agent land a byte the suite doesn't bless. This method is where that discipline comes from — the gates were the practice first, and the systems inherited it.

Which leaves one obvious question: who reviewed the page about the review process? The same pipeline. Scouts mined the build history of the other two case studies, angled writers drafted, a builder built, and four reviewer agents went at this page with the exact lenses described above — including the sensitivity auditor, which had opinions. I triaged the findings, applied what survived, and wrote down every rejection.

A page produced by the pipeline can't certify the pipeline — that's the same conflict of interest the gates exist to catch. So don't take this page's word for it. A run is twenty to thirty minutes; I'll do one in front of you.

07 07 What this demonstrates

Three claims, receipts above

AI engineering

Multi-agent pipelines as production tooling — scouts return receipts files so writers draft only pre-verified claims, fan-outs run on assigned angles instead of a shared prompt, and a judge scores every option against explicit criteria. The same craft as the day job: AI-agent skills on MCP servers at Oracle.

Orchestration

Scripted phases, fan-outs, and barriers — every result journaled append-only the moment it lands, so an interrupted run resumes from the last barrier instead of restarting. The homepage redesign, the largest run, finished in about two hours.

Judgment

Every verdict on the record — each finding fixed or rejected with a written reason, including overruling a technically-correct sensitivity flag and shipping the fix that killed a flattering line.
